## 3. Version-scoped implementation and evidence rule

For every row above, P-17 may count a capability as implemented only when all of these exist for the same source hash:

1. canonical registry/router mapping;
2. provider-neutral semantic grammar and exact IR field use;
3. success, boundary/failure and quantitative assertions where applicable;
4. one original positive fixture and one original boundary fixture;
5. semantic validator and render smoke in each owner-approved static mode when the relevant visual phase is authorized;
6. accessibility data/read-order check;
7. provenance receipt naming this matrix row and confirming no upstream expression was reused.

P-16 creates none of those runtime or gallery artifacts. It locks the contract against which later separately authorized work must be reviewed.
